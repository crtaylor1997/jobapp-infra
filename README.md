# jobapp-infra

Terraform for the job application pipeline on AWS.

```
scripts/
  bootstrap-state.ps1   creates the S3 state bucket + <stack>/<env>.backend.hcl
  tf.ps1                runs terraform for one stack + env (always use this)
modules/                reusable modules
  network/              VPC, private subnets, S3/DynamoDB gateway endpoints
  lambda/               ECR repo, IAM role, log group, container-image Lambda
network/                stack: one VPC per env
lambda/                 stack: worker Lambda per env
  providers.tf main.tf variables.tf outputs.tf
  dev.tfvars  prd.tfvars              per-env settings
  dev.backend.hcl  prd.backend.hcl    per-env state (generated by bootstrap)
```

Each piece of infra is its own stack folder with its own state per environment,
so you can plan/apply/destroy the network and the Lambda independently. Anything
that differs between environments goes in `<env>.tfvars`.

| Stack | dev state | prd state |
|---|---|---|
| network | `network-dev.tfstate` | `network-prd.tfstate` |
| lambda | `lambda-dev.tfstate` | `lambda-prd.tfstate` |

Always run Terraform through `scripts/tf.ps1 <stack> <env> <command>`. It pairs
`<env>.tfvars` with `<env>.backend.hcl` and gives each env its own data dir
(`<stack>/.terraform-<env>`), so you can't apply prd settings to dev state, and
switching envs never needs `init -reconfigure`.

| Setting | dev | prd |
|---|---|---|
| VPC CIDR | `10.0.0.0/16` | `10.1.0.0/16` |
| Lambda log retention | 7 days | 30 days |
| ECR `force_delete` on destroy | yes | no |

To add a stack (e.g. `storage/`): create the folder with a `providers.tf`, then
re-run `bootstrap-state.ps1` to generate its backend files. If it needs another
stack's outputs, read them with `terraform_remote_state` (key `<stack>-<env>.tfstate`).

## Network foundation (`modules/network`)

| Piece | Details | Cost |
|---|---|---|
| VPC | DNS hostnames on | free |
| Private subnets | 2 x `/20` across 2 AZs, no public IPs | free |
| Gateway endpoints | S3 + DynamoDB routed privately from the private route tables | free |
| Lambda security group | No inbound, HTTPS (443) outbound only | free |
| Default SG | All rules stripped | free |
| NAT (optional) | `enable_nat_gateway = true` adds public subnets, IGW and one NAT | about $32/mo + data |
| Flow logs (optional) | `enable_flow_logs = true`, CloudWatch, 14-day retention | usage-based |

## Lambda (`modules/lambda`)

Each env gets a `jobapp-<env>-worker` function with:

- **ECR repo** of the same name: immutable tags, scan on push, keeps the last 10 images
- **IAM role** `jobapp-<env>-worker-role`: may only write to its own log group.
  The S3 and DynamoDB stacks will attach their policies to this role.
- **Log group** `/aws/lambda/jobapp-<env>-worker`
- **Function**: arm64, 512 MB, 60 s timeout, `ENVIRONMENT` env var. It is only created
  once `image_tag` is set in `lambda/<env>.tfvars`, because a container Lambda can't exist before its
  image is in ECR.

## Cost decision: Lambda runs outside the VPC

To keep costs close to $0, the Lambda is **not** attached to the VPC. It runs in
AWS's managed network with direct internet access (job boards, LLM APIs) and
reaches S3 and DynamoDB over their public endpoints, secured by IAM and TLS.

Putting a Lambda in a public subnet would not work: a VPC-attached Lambda never
gets a public IP, so its only route to the internet is through a NAT gateway.

The VPC is still deployed (it's free). To move the Lambda in later, pass
`vpc_subnet_ids = module.network.private_subnet_ids` and
`vpc_security_group_ids = [module.network.lambda_security_group_id]` to the worker
module and set `enable_nat_gateway = true` (about $32/mo).

## Deploy

Prereqs: Terraform >= 1.10, AWS CLI v2 with credentials (`aws configure` or `AWS_PROFILE`).

```powershell
# 1. State bucket + every <stack>\<env>.backend.hcl (safe to re-run)
.\scripts\bootstrap-state.ps1                    # options: -Region, -Profile, -Environments, -Force

# 2. Network (inits automatically on first use)
.\scripts\tf.ps1 network dev plan
.\scripts\tf.ps1 network dev apply

# 3. Lambda: first apply creates the ECR repo, role and log group
.\scripts\tf.ps1 lambda dev apply
.\scripts\tf.ps1 lambda dev output ecr_repository_url
#    push an image there, set image_tag = "<tag>" in lambda\dev.tfvars, then
.\scripts\tf.ps1 lambda dev apply                # creates the function
```

Promote to prd by pushing the same image to the prd ECR repo, setting the same tag
in `lambda\prd.tfvars`, and running `.\scripts\tf.ps1 lambda prd apply`.

## Tests

Mocked AWS provider, no credentials needed:

```powershell
cd modules\lambda; terraform init; terraform test
cd ..\..\network;  terraform init -backend=false
terraform test -var-file=dev.tfvars
terraform test -var-file=prd.tfvars
```
